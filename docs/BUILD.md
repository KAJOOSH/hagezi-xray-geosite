# راهنمای ساخت و انتشار

## ساخت محلی

نسخهٔ Go موردنیاز در [فایل go.mod](../go.mod) مشخص شده است. دستور زیر فهرست‌های رسمی HaGeZi را می‌گیرد و فایل هر بسته، هش‌ها، مشخصات نسخه و آرشیو منابع را در `dist/` می‌سازد.

```sh
go run -mod=readonly ./cmd/geosite
```

## ساخت در GitHub Actions

گردش‌کار [Update GeoSite](../.github/workflows/update.yml) هر روز ساعت ۰۳:۱۷ به وقت UTC اجرا می‌شود. برای اجرای دستی، در **Actions → Update GeoSite → Run workflow** شاخهٔ پیش‌فرض را انتخاب کنید. در مخزن جدید، گردش‌کار باید روی شاخهٔ پیش‌فرض موجود باشد و اجازهٔ نوشتن در مخزن را داشته باشد. گیت‌هاب ممکن است زمان‌بندی مخزن عمومی بدون فعالیت را متوقف کند. [راهنمای زمان‌بندی GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## شمارهٔ نسخه و خروجی

شمارهٔ نسخه در Actions قالب `vYYYYMMDD.N` دارد. بخش تاریخ بر اساس UTC و `N` شمارهٔ اجرای گردش‌کار است. ساخت محلی به‌جای شمارهٔ اجرا از ساعت ساخت به قالب `HHMMSS` استفاده می‌کند.

گردش‌کار تاریخ ساخت، نسخهٔ HaGeZi، هش‌ها و شناسهٔ کامیت سازنده را در `manifest.json` ثبت می‌کند. کامیت شاخهٔ `generated` شمارهٔ نسخه و زمان کامل ساخت را دارد. این شاخه فایل و متن منبع TIF Medium را در نشانی قبلی هم ارائه می‌کند. در **Releases** هر بسته فایل مستقل دارد. فایل `checksums.sha256` برای فایل‌های داده و `sources.zip` در دسترس است. آرشیو منابع متن اصلی هر بسته را با نام درج‌شده در `manifest.json` نگه می‌دارد. اگر محتوای ورودی و خروجی همهٔ بسته‌ها یکسان باشد، گردش‌کار همان نسخه را حفظ می‌کند. اگر نسخه هنوز منتشر نشده باشد، اجرای بعدی می‌تواند انتشار را ادامه دهد.
